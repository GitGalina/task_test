# TestPad Analyzer — навык работы с репозиторием

Веб-приложение для анализа качества тестов и результатов студентов на платформе Online Test Pad (OTP). Локальный проект преподавателя, публикуется на https://github.com/GitGalina/task_test

## Структура проекта

```
server.py        Flask-приложение: все API-эндпоинты (/api/login, /api/status,
                 /api/disciplines, /api/diagnostics и др.), раздача static/
otp_client.py    Клиент OTP на Playwright (sync): вход в кабинет, проход теста
                 по публичной ссылке, парсинг статистики JS-сниппетами
                 (_ANSWER_KEY_JS, _SUMMARY_JS) в контексте страницы
analyzer.py      Локальные эвристики качества вопросов (без сети): формулировки,
                 дистракторы, длина вариантов; итоговая оценка 0–100
tests_loader.py  Excel → data/tests.json (столбцы «папка»/«дисциплина»/«тест»/«ссылка»)
static/          Frontend без сборки: index.html, app.js, style.css.
                 Состояние приложения — объект fileState в app.js
data/            tests.json (список тестов), otp_state.json (сессия кабинета —
                 СОДЕРЖИТ COOKIES, никогда не публиковать)
start.bat        Запуск с автопроверкой зависимостей (flask, pandas, openpyxl,
                 playwright, chromium) и портом 5000
README.md        Описание проекта для GitHub (версия/дата в строке «> Версия:»)
task2_MVP.md     Спецификация MVP: границы, критерии готовности, техрешения
```

## Ключевые архитектурные ограничения (не нарушать)

- Flask запускается с `threaded=False`, один процесс — Playwright sync несовместим
  с реентерабельностью; доступ к браузеру только через worker-поток и `RLock`.
- Один экземпляр `OTPClient()` на процесс (глобальная переменная в server.py).
- Корректность ответов пересчитывается на сервере по ключу из редактора,
  а не по колонкам таблицы статистики OTP.
- Таблица статистики OTP бывает с двумя строками заголовка (ВТ) и с одной
  (ММ 04, вопросы «ввод ответа») — парсер обязан поддерживать оба варианта.
- Сессия кабинета должна переживать перезапуск сервера (`data/otp_state.json`,
  пароль не сохраняется).
- Frontend — чистый HTML/CSS/JS без npm, сборщиков и CDN.

## Запуск сервиса

```powershell
# быстрый старт (зависимости уже установлены):
python server.py          # → http://127.0.0.1:5000

# полный запуск с проверкой зависимостей:
.\start.bat
```

Проверка живости: `Invoke-WebRequest http://127.0.0.1:5000/api/status`.
Если порт занят — сервис уже запущен, второй экземпляр не поднимать.
Останавливать фоновый сервер: найти процесс python, слушающий :5000
(`Get-NetTCPConnection -LocalPort 5000`).

## Внесение изменений

- API-логика → `server.py`; работа с сайтом OTP → `otp_client.py`;
  эвристики оценки → `analyzer.py`; интерфейс → `static/app.js` (+ html/css).
- После правок Python: `python -m py_compile server.py otp_client.py analyzer.py tests_loader.py`
- После правок JS/HTML: проверить отсутствие ошибок в консоли браузера
  (через Playwright MCP открыть http://127.0.0.1:5000 и пройти основной сценарий:
  выбор дисциплины → клик по тесту → анализ → раздел результатов).
- Новые эндпоинты добавлять в стиле существующих: jsonify, обработка OTPError.
- Комментарии и строки UI — на русском языке, как в остальном коде.

## Проверка перед публикацией

1. `python -m py_compile` всех .py — нет синтаксических ошибок.
2. Сервер стартует, `/api/status` отвечает, основные сценарии в браузере без ошибок консоли.
3. `git status` — в индекс не попали: `data/otp_state.json`, `__pycache__/`,
   `.playwright-mcp/`, временные логи (проверить .gitignore).
4. Коммит с понятным сообщением (кратко, в повелительном наклонении).
5. `git push` в `origin main` (https://github.com/GitGalina/task_test).
   Коммитить и пушить только по явной просьбе пользователя.
