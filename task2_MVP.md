# Task 2 — TestPad Analyzer: идея и ограничение до MVP

## 1. Идея задачи

Преподаватель ведёт учебные курсы и составляет тесты на платформе **Online Test Pad** (OTP). Список тестов по дисциплинам хранится в Excel-файле («СПИСОК тестов TestPad.xlsx»), где на каждый тест дана публичная ссылка.

Возникает практическая задача: **оценить качество теста до того, как его напишут студенты**, и **проанализировать реальные результаты** после прохождения. Вручную это делать неудобно: нужно открыть каждый тест, просмотреть все вопросы, оценить формулировки, варианты ответов, а затем выгружать статистику из личного кабинета OTP.

**Продукт — веб-приложение «TestPad Analyzer»**, которое автоматически:

1. Загружает список тестов из Excel-файла и группирует их по дисциплинам.
2. Проходит каждый тест **по публичной ссылке** (без создания записи о результате) и собирает вопросы с вариантами ответов.
3. Оценивает качество каждого вопроса **локальными эвристиками** (качество формулировок, правдоподобность дистракторов, длинна вариантов, наличие верного ответа и т. п.) и выставляет итоговую оценку теста.
4. **Загружает реальные результаты студентов из личного кабинета** (сопоставляя Excel-ссылку с id теста в кабинете) и показывает визуальный разбор: сводные метрики, распределение баллов, матрицу «студент × вопрос», проблемные вопросы, повторяющиеся ошибки и рекомендации преподавателю.
5. Даёт возможность экспортировать отчёт в PDF.

## 2. Роль личного кабинета

Публичный проход теста даёт только **структуру вопросов** (текст, варианты, правильный ответ можно вычислить по ключу из редактора). Данные о **реальных ответах студентов** доступны только внутри личного кабинета преподавателя. Поэтому приложение:

- хранит сессию входа в OTP (cookies) в локальном файле `data/otp_state.json` (пароль не сохраняется);
- сопоставляет тесты из Excel с тестами кабинета по названию (`_resolve_account_test`);
- читает матрицу ответов со страницы `/statistics/summary` и ключ ответов из редактора `/tests/{id}/questions`;
- считает «верно/неверно» по каждому ответу, агрегирует статистику по группе.

## 3. Границы MVP (что входит)

Для MVP принимаем следующий объём:

- **Входные данные** — только Excel-файл фиксированного формата («СПИСОК тестов TestPad.xlsx»: дисциплина → список тестов с публичными ссылками).
- **Раздел 1. Дисциплины и тесты** — выбор папки (дисциплины) и теста, клик по тесту запускает анализ качества по публичной ссылке.
- **Раздел 2. Анализ теста** — перечень вопросов с вердиктами локальных эвристик и итоговой оценкой (0–100).
- **Раздел 3. Анализ результатов**:
  - кнопка «Загрузить реальные результаты из кабинета» (используется тест из раздела 1);
  - сводные карточки (завершённые попытки, средний балл, сдали ≥60%, сложные вопросы);
  - распределение результатов по диапазонам;
  - список проблемных вопросов с верными ответами;
  - матрица «студент × вопрос» (верно/ошибка/нет ответа) с поиском по студенту;
  - темы, повторяющиеся ошибки, рекомендации преподавателю;
  - встроенные демо-данные как резервный режим.
- **Кабинет OTP** — вход/выход, восстановление сессии, загрузка статистики только по **одному выбранному тесту** (не по всей дисциплине сразу).
- **Экспорт PDF** — простая печатная версия текущего раздела.
- **Локальный запуск** — приложение запускается на `http://127.0.0.1:5000`, без БД и внешних сервисов.

## 4. Что осознанно НЕ входит в MVP (вне границ)

- Авторизация пользователей приложения (многопользовательность, роли).
- Пакетная загрузка статистики по всем тестам дисциплины/всего кабинета за один клик.
- Хранение истории прохождений и сравнение динамики по неделям/попыткам.
- Импорт тестов из других источников (не Excel), другие форматы файлов.
- Редактирование тестов или вопросов внутри приложения.
- Расширенные метрики валидности/надёжности теста (IRT, дифференцирующая способность и т. п.).
- Поддержка иных платформ кроме Online Test Pad.
- Распределённый/облачный деплой, HTTPS, боевой хостинг.

## 5. Критерии готовности MVP (Definition of Done)

- Приложение стартует одной командой и работает локально.
- По клику на тест из Excel-файла собираются вопросы с публичной ссылки и выводится оценка качества.
- Для теста, у которого в кабинете есть попытки, кнопка «Загрузить реальные результаты» возвращает корректные данные: число попыток, верные/неверные ответы по ключу, сводные метрики.
- Рендер корректно работает и для тестов с двумя строками заголовка таблицы статистики (ВТ), и с одной (ММ 04, вопросы типа «ввод ответа»).
- В консоли браузера нет ошибок при основных сценариях.
- Сессия кабинета переживает перезапуск сервера (`data/otp_state.json`).

## 6. Принятые технические решения (кратко)

- Backend: Python + Flask (один процесс, `threaded=False`), один клиент OTP на процесс.
- Браузерная автоматизация: Playwright (sync) в отдельном worker-потоке, чтобы не конфликтовать с asyncio; блокировка `RLock` (реентерабельная).
- Парсинг статистики: два JS-парсера (`_ANSWER_KEY_JS`, `_SUMMARY_JS`), запускаются в контексте страницы; корректность ответов пересчитывается на сервере по ключу, а не по колонкам таблицы OTP.
- Frontend: чистый HTML/CSS/JS, без сборки; состояние приложения в JS (`fileState`), статус загрузки статистики — спиннер + текст.
- Данные: `data/otp_state.json` (сессия), `static/data/tests.xlsx` (список тестов).
